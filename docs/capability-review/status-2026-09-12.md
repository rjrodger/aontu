# Status report — 2026-09-12

*A dated snapshot of one assessment, not a register.*
[`progress.md`](progress.md) remains **authoritative** for per-phase
status. This file records what an audit of the **module system** found
on 2026-09-12 — the G6 and G10 rows, the six design notes and the
executable specification in `aontu-lang/system`, the transparency client
in `aontu-lang/mod`, the Cloudflare precedent in `aontu-lang/web`, and
the live state on npm, in DNS and on the forge. Where the two disagree,
the register is right and this file is stale.

**This commit changes no register row.** Every regrade it argues for is
written here as a recommendation, because a status changes in the commit
that changes it. The one word it asks the maintainer to move — G10 phase
2, from LANDED to PARTIAL — is §5 item 9.

## Headline

**The registry does not exist yet, and the trust argument the design
rests on is not yet true.** `pkg.aontu.dev` is NXDOMAIN; there is no
registry bucket, no write-path Worker and no registry `wrangler.json` in
any of the four repositories — the only Worker in the tree is the live
docs site. `@aontu-lang/mod` is unpublished, into a scope that answers
404 to an unauthenticated probe. `mod get` and `mod publish` exit 2 in
both ports.

What is real is narrow and green: the local module half in both ports
(G6, five rows LANDED, 43/43 and use case 11 34/34 under both binaries),
a transparency-log verifier that reproduces a live Rekor v2 checkpoint
root from tiles (46/46, 100 % coverage, 720 vectors byte-identical
across two repositories), and an executable specification of the whole
protocol holding 62 checks under the engine it pins.

The design is decided on paper — [ADR-019](../../ADR.md#adr-019--the-project-stores-module-bytes-and-federates-the-log),
[ADR-020](../../ADR.md#adr-020--a-module-path-is-domainpath-and-the-domain-is-a-proved-namespace),
[ADR-021](../../ADR.md#adr-021--the-project-hosts-private-packages-with-authenticated-reads),
[ADR-022](../../ADR.md#adr-022--compatibility-is-computed-so-the-major-leaves-the-name) and
[ADR-024](../../ADR.md#adr-024--the-forges-token-authorises-a-publish-and-sigstore-is-one-provider-of-the-proof-not-its-definition),
all between 2026-09-04 and 2026-09-06 — but conditional on two things
that are false today: the client-verification contract lives in the
private `system` repository the split rule forbids, and an operator key
has returned four ways after being declared retired.

**One new defect sits on the integrity path.** TypeScript 0.60.0 and
later compute a different canon-hash from Go for the shape the
specification is built on, so a lockfile written by one port fails the
other's `mod verify` over an untouched store. Beside it, a defect
carried since [`status-2026-09-05.md`](status-2026-09-05.md) and
unchanged at HEAD: the `mod` verbs evaluate vendored third-party modules
at the default `system` capability while refusing `--trust`.

## 2. The finding that moves the priorities

**The canon-hash is port-dependent at HEAD, and nothing records it.**

On `spec/registry.aon` in `aontu-lang/system`:

| Engine | `aontu hash --trust root:spec spec/registry.aon` |
|---|---|
| TypeScript 0.57.0, 0.58.0, 0.59.0 | `aon1-yVCc2Q9gxIWwKB5rocsSWcuBxtd2g8nE3qX6w20yykE` |
| TypeScript 0.60.0, 0.61.0, 0.62.0 | `aon1-wyMpq-lY4AGtctwe5f5zup8CcItpieNNKjDR54IiKBw` |
| Go v0.1.15 through v0.1.20 | `aon1-yVCc2Q9gxIWwKB5rocsSWcuBxtd2g8nE3qX6w20yykE` |

The evaluated documents are byte-identical at 71,852 bytes, so the two
engines agree on meaning and only the hash renderer disagrees. The
difference is one conjunct in the element type of a list spread
template: where the source says `refuse?: [&: refer() & path()]`,
TypeScript from 0.60.0 renders `refer()&refer()` and Go renders
`refer()&refer()&path()`. It occurs at 43 sites — forms of 73,921 and
74,222 bytes, `path()` 94 against 137 — and `close(` is 212 in both, so
adopting Go's form on this document buys no `close()` discrimination.
Both ports render the doubled `refer()`, which is itself unexplained.

**Why it survived.** `test/spec/hcanon.tsv` holds 53 rows and not one of
them mentions `path(`. The parity ledger `test/spec/divergent.tsv`
carries four OPEN entries, none of them this, and by design contributes
no executable rows — it is a file of comments read by both runners. So
both CI matrices are green over the divergence, and the shared suite
cannot catch it until a row exists.

**What it costs.** A lockfile written by Go's `mod tidy` fails
TypeScript's `mod verify` on an untouched store, for the exact shape the
registry specification uses. ADR-001 promises the two implementations
are one; on the integrity pin they are not. Any pin the registry stores
before this is fixed is a pin one port will reject.

**How to decide it.** [ADR-001](../../ADR.md#adr-001--typescript-and-go-stay-at-full-parity-driven-by-a-shared-spec)
supplies the default: TypeScript is canonical, so the form is
`aon1-wyMpq…` and the burden is on whoever wants Go's. The one ground
for overturning that default is safety — a hash form that carries less
than the old one can "report NO CHANGE for a change of meaning, which is
the one direction a pin must not fail in" (`CHANGELOG.md:1022-1032`, the
0.60.0 entry). That argument is testable: write an `hcanon` row where
the TypeScript form fails to discriminate two documents of different
meaning. If the row exists, take Go's form; otherwise take TypeScript's
per ADR-001. The measurement so far weakens the safety argument, since
`close(` is equal in both forms.

Fix the engine rather than writing a ledger entry. Both renderers are in
this repository (`ts/src/hcanon.ts`, `go/hcanon.go`) and depend on
nothing pinned, which is neither excuse `divergent.tsv:18-33` admits.
Shared rows come **after** the fix, because a row cannot exist until
both ports agree. The price of adopting TypeScript's form is one line:
`spec/hash.txt` is the only real pin in `system`, and the gate's engine
bump.

## 2a. What a pin promises, given bundled models

A second, quieter problem sits underneath the first. Eight bundled
models — `aontu/system`, `view`, `code`, `render` and four `render/lang`
profiles — are inside every canon-hash a module carries: a two-line
document that includes `aontu:system` hashes with a 1,516-byte form
against 8 bytes for `x: 1`, identically in TypeScript 0.62.0 and Go
v0.1.20. Every one of the eight is still headed *"EXPERIMENTAL until the
distribution layer can version it by canon-hash"*, and the set went from
zero to eight with a rename in six days. Nine pin moves landed in five
days, eight of them model *content* rather than hash form; more are
queued in the unreleased section, one marked BREAKING.

A scheme-id bump cannot address this class — a registry cannot mint
`aon2-` because a vocabulary gained a field. `T.LockEntry` is closed over
four pins with no engine identity, so `lock_mismatch` cannot distinguish
"the package changed" from "your engine changed", and `refreeze` exists
in four design notes and in neither port. `mod tidy` is not refreeze:
`ts/src/mod-tool.ts:246` overwrites the stored pin with whatever the
current engine computes.

Until the bundled set is declared stable under its own ADR, the archive
digest is the authoritative immutable pin and the canon-hash is an
advisory annotation. That is a defensible position; it is not the
position the documents currently state.

## 4. What is decided, and what is only provisional

Settled, and not to be reopened without a new entry: bytes stored and
the log federated (ADR-019); the read path a static, GOPROXY-shaped
bucket, mirrorable by copy; two pins in a specified order; provenance as
forensics rather than a control; moderation shipping *with* publish;
`<domain>/<path>` names never resolved, with the subject pair as the
signing identity (ADR-020); no major in the path and compatibility
computed in three components (ADR-022); the private tier (ADR-021); and
the token authorising while Sigstore merely provides the proof
(ADR-024).

Two of those need a footnote the documents do not carry:

- **"No code on the read path" is true of the objects only.** The same
  design assigns the read path three active edge behaviours — path-shape
  rejection before an object read, one-shot 404 caching, and zone rate
  limiting (`spec/layout.aon:43-47`). Those are Cloudflare rules living
  in an account with no repository, no review and no deploy path.
- **"Provenance is forensics" does not weaken property 1.** The control
  is ADR-024's proof contract; Sigstore is one provider of it. What a
  user is asked to trust is the contract, not the log.

Dated in `aontu-lang/system` with no ADR, and unadopted in the engine:
`pkg.aontu.dev` as a base URL; the registrar held away from Cloudflare;
`publish` at top level with `add` and `get` both existing;
`mod.aon`/`mod-lock.aon` becoming `pkg.aon`/`aontu_meta/pkg-lock.aon`;
and no migration shims. Three naming schemes now coexist across the
engine, the specification and the notes.

The nine provisional choices in `spec/params.aon` are all ratifiable now
except the durations. `lock_pins` should gain a fifth field — the engine
identity, which `aontu mod manifest` already emits — and the byte pin's
name should be settled at `archive`, since the engine calls it `oci`,
the specification calls it `archive` and `PATCHING.0.md` calls it
`integrity`. The thirteen numbers can stay provisional; they become
commitments the moment the first archive is stored.

**Eight spec choices carry security weight and are not marked
provisional**, which `registry.aon:20-23` makes the rule. The worst is
the advisory object: `/advisory/<package>.aon` is mutable on a
60-second TTL, unsigned, with no expiry and **no timestamp of any
kind**, so it is the one mutable object a client cannot date. Nothing in
`ops.acquire` verifies it, the rollback check protects the version list
and has no analogue for it, and retraction has exactly one carrier —
this file. The commissioned survey asked for a signed, append-only
advisory; the specification renders it unsigned and overwritten in
place.

## 5. Open decisions

Ordered by what they block, not by size. The full argument for each is
in the sections above.

1. **The canon-hash rendering rule.** §2. Blocks the engine pin move in
   `system`, the `refer() &` restoration on `Step.phase`, and the
   portability of every stored `aon1-` pin. Take TypeScript's form per
   ADR-001 unless a discriminating `hcanon` row can be written.
2. **What a canon-hash pin promises, given bundled models.** §2a. Keep
   the status quo but make it honest: retire the EXPERIMENTAL headers
   under an ADR when the set stops moving, store the archive digest as
   authoritative meanwhile, add the engine-identity field, and specify
   `refreeze`.
3. **Key custody for the operator key federation was said to retire.**
   It has returned four ways: the tombstone signature, the key provider,
   a signed expiring `@v/list`, and the advisory the survey asked to be
   signed. One ADR covers all four. Recommended: the write-path Worker
   holds no signing key; tombstones are signed offline by a named human
   as a runbook step; the key provider is limited to publisher-held keys
   on the public tier; the signed `@v/list` is declined for v1; and the
   residual credentials are enumerated before P2.
4. **The Sigstore provider: which verifier, and how a bundle maps onto
   the contract.** Specify the mapping in the `mod` contract first.
   Refuse Rekor v1 bundles explicitly. Do not let this block the key
   provider or the self-publish milestone.
5. **Where the contract lives, and which way the dependency points.**
   ADR-024 says `mod`; it is in `system`. Move it as gated aontu
   documents with an engine devDependency **pinned to a released
   version, never HEAD** — running the same gate against HEAD fails on
   the hash today, which is exactly what the pin exists to prevent —
   and publish `mod` before the engine consumes a new contract, so a
   contract edit is two pull requests in a fixed order.
6. **Which legal person operates the registry and holds the account.**
   The longest pole; no code shortens it. The entity does not block the
   first measurement, but the *account* choice blocks P1: the R2 custom
   domain requires the zone in the Cloudflare account, and that zone
   already sits in an account shared with another site, so deciding
   after creating the bucket means a DNS cutover of the live docs site.
7. **Off-account backup: provider, cadence, holder, and what it does
   with a tombstone.** Entirely absent — three grep hits across the
   notes, no destination, no holder, no row in the 27-row gap table —
   while the stated emergency remedy is to serve from a mirror and there
   are no mirrors at launch. Attach a copy to P1, where the corpus is
   334 KB of first-party content and no publisher licence or
   notice-and-action question attaches yet.
8. **Explicit email-SAN refusal**, which ADR-024 implies structurally
   but no code, vector or ADR text states. One publish step.
9. **G10 phase 2's status word**, and the mechanism for the first
   `@aontu-lang/mod` publish. Recommended: grade PARTIAL, and change the
   row in the same commit that publishes. Claiming the npm scope is not
   part of this decision and depends on nothing.
10. **The `mod` verbs under the trust contract.** Fix, do not narrow the
    documentation: these verbs become `sync` and `verify`, and must not
    carry the hole forward.
11. **Ratify the naming with an ADR here.** CLI.0's four decisions plus
    ADR-022's engine consequences. CLI.0's "no shims because nothing is
    public" premise is contradicted by the tree: 0.53.0 and later are on
    npm, hand-vendoring is the documented cold start, and both ports
    already carry a refuse-and-name shim for the `aontu_meta/` move.
12. **Freshness, and what covers the advisory.** First-seen only for v1,
    stated as a known gap; sign the advisory once item 3 produces a key.
13. Smaller, each argued above: private-tier provenance and phase; the
    escape hatch for an intended outcome change; the `aontu-release/v1`
    leaf, which ADR-024 supersedes; the `system` engine pin move, whose
    Go half can land today; the write-path deploy path and the
    credential scope at bucket creation; the compat gate at P2 and the
    fate of `mod manifest`; the legal-surface choices; the project's own
    namespace; the survey's unanswered bundling contradiction; the
    gap-document rewrite; `PATCHING.0.md`; and the use-case corpus under
    Go in CI.

## 7. Risks

- **The integrity pin is port-dependent today**, and both CI matrices
  are green over it.
- **Stored pins have no upgrade story**, and the moving part is not one
  a scheme id can fix: eight of the last nine pin moves were bundled-model
  content.
- **One open engine defect still sits on the hash path.** `BUGS.md` §82:
  a module whose vocabulary uses a recursive alias is pinned by a canon
  that does not re-evaluate to itself, identically in both ports.
- **Key custody was declared retired and has returned four ways**, while
  the deploy path for a Worker holding credentials is undecided and the
  only precedent deploys whatever merges to `main`.
- **Verification by the client is the whole integrity argument, and the
  client verifies no bytes yet.** The contract lives in a private
  repository the split rule forbids, so "independently auditable client"
  is false today, and a phase-3 implementer following the register finds
  nothing in `mod`.
- **Retraction has one unsigned, undateable carrier.**
- **The `mod` verbs evaluate vendored third-party modules unconfined**,
  and ADR-022 puts an evaluator on the write path whose only declared
  bounds are passes, revisits and depth. On the write path the real
  bounds come from the platform, and nobody has measured whether a
  worst-case publish fits one invocation — so the denial-of-service
  question and the topology question are the same unanswered question.
- **The read path's security controls live where nothing in these
  repositories can see them.**
- **The design declines to defend the dominant real attack** — a
  compromised publisher account or CI — and the one cheap control the
  evidence rates highest among the unbuilt, the trust set at resolve
  time, appears in no register row and no spec step.
- **The project requires of publishers a provenance it achieves on one
  of its own thirteen channels.**
- **Nothing legal exists**, and the e-Evidence preservation answer rests
  on a property of unwritten code and an unconstrained credential.
- **Account and domain concentration, with no copy anywhere.** A
  suspension takes the read path, the name and the only copy together,
  despite ADR-019's stated exit.
- **Cost is unbounded under attack**, and both the $20 column and the
  cache-miss arithmetic rest on rates the note itself flags as
  unverified.
- **Sigstore's shape is moving under the design**: the verifier is
  Ed25519 only, witness cosignatures on Rekor v2 checkpoints cannot be
  verified, and `x/mod` is nine releases behind with no scheduled review.
- **The engine and the specification disagree on the name of every
  module**, and each release accretes fixtures against the shape ADR-022
  removed.
- **The record is drifting faster than it is corrected.** Six ADRs in
  eight days reversed one axis twice; the register still plans OIDC
  binding and cosignatures for a log the project will not run; the
  commissioned survey is cited twenty times and tracked nowhere; the
  specification is held to 0.57.0 while users install 0.62.0; and no
  issue in any repository mentions the registry, so an unattended agent
  or a new contributor cannot find the work.

## Method, and its confidence

Twelve auditing agents read the tree in parallel — one per area, across
the four repositories, the six design notes, the executable
specification, the engine's module surface, the register, and the live
state on npm, in DNS and on the forge. Each was held to an evidence
rule: a path with a line number, a command with its output, a commit, or
a URL. They returned 559 facts.

Every fact then went to a second agent whose brief was to **refute** it:
re-open the file, re-run the command, re-probe both ports. Three
independent drafts were written from a security lens, a sequencing lens
and a governance lens, merged by a fourth agent, and then put to three
critics — completeness, aim, and rigour — which returned 12 gaps, 17
unsupported claims, 12 contradictions and 14 misordered steps. Those
were filled or corrected before this text.

The headline findings in §2 were re-derived by hand afterwards: six
engine versions across both ports run against `spec/registry.aon`, the
canonical forms diffed byte by byte, the suite and ledger coverage
counted, and the CLI behaviour reproduced at HEAD.

As with earlier reports in this series, **this is written by the agent
that did the work**, and it has no human verifier. The claims about
external state — the registrar record, the npm scope probe, the
unverified cost rates, the legal memorandum that is in no repository —
are marked where they are soft.
