# Generate Rails code with aontu templates

The Rails example uses seven Ruby templates and one aontu document to
write the application files marked as generated. A template specifies
both the output paths and the rules that fill them. Read the
[model guide](model.md) first for setup and the entity properties.

## Separate instructions from output

Open the [routes generator](../gen/routes.rb). Lines beginning with `#-`
contain aontu instructions. Other lines provide Ruby output:

<!-- source: ../gen/routes.rb -->
```ruby
#- @"../model.aon"
#-
#- aontu: Code: units: [
#-   {
#-     path: "config/routes.rb"
#-     lang: "ruby"
#-     decls: [
#-       {
#-         k: "frag"
#-         of: [
# Generated by `aontu render` from model.aon. Do not edit.
```

The import loads `model.aon` relative to the generator file.
`aontu.Code.units` is the list of files to render. This unit writes `config/routes.rb`
relative to the output directory, and `decls` holds its declarations.
A `frag` declaration contains fragments of target text.

Ruby treats every `#-` line as a comment. This lets the template remain
parseable Ruby, with placeholders where generated values will go.
Check its syntax:

```sh
ruby -c gen/routes.rb
```

A syntax check does not run the template as a Rails application. aontu
must first evaluate the marked instructions and substitute model values.

## What render expects

`aontu: Code: units: [...]` is shorthand for
`aontu: { Code: { units: [...] } }`.
The `render` command expects this structure in its input document and
checks it against the bundled `aontu:code` vocabulary. Ordinary aontu
models do not need it; it is the contract for code generation.

Each unit supplies a file `path`, a target `lang`, and a list of `decls`.
A declaration with `k: "frag"` supplies target-text fragments in `of`.
This example writes that text explicitly; the language name does not
make aontu invent a Rails implementation.

The generator's import and its own declarations form one document.
The imported file supplies `service` and `entity`; the generator adds
`aontu.Code.units`, computed from those values. You pass the generator to
`render`, not `model.aon` on its own. By default, `render` reads from
the document root. `--at` selects another location when needed.

See the [render command reference](../../../../docs/reference-api.md#aontu-render)
for the full input contract and output options.

## Follow one value into a route

The root-route rule selects the service's root value:

<!-- source: ../gen/routes.rb -->
```ruby
#-         of: emit([$.service.root], {
#-           match: string
#-           replace: ROOT: _
#-           body: [
  root "ROOT"
#-           ]
#-         })
```

[`emit`](../../../../docs/reference-language.md#transforming-emit) visits
the selected values and uses the first matching rule.
Here the selection is a one-item list containing `"planets#index"`.
`match: string` admits that value, `_` refers to it, and `replace`
substitutes it for `ROOT` in the output line.

Inspect the rendered file without writing it:

```sh
aontu render --stdout gen/routes.rb
```

The root line in the output is:

```ruby
  root "planets#index"
```

The other rules iterate over entities to write browser routes, API
routes, and action routes. Replacement names must not overlap: aontu
refuses a table with both `COLLECTION` and `COLLECTION_HELPER`.

## Produce one file per entity

The [Active Record generator](../gen/model.rb) builds its units with
`emit($.entity, ...)`. For each matching entity it computes the path
from `.id`, such as `app/models/moon.rb`.

Inside that unit, a second rule emits the class body. `.class` is the
current entity's class name. A nested selection of required fields
writes presence validations:

<!-- source: ../gen/model.rb -->
```ruby
#-               emit(filter(.field, { required:true }), {
#-                 match: name: string
#-                 replace: FIELD: .name
#-                 body: [
  validates :FIELD, presence: true
#-                 ]
#-               })
```

`filter` selects fields with `required: true`; the rule reads each
selected field's `name`. For Moon, this produces validations for
`diameter`, `id`, `kind`, `name`, and `planet_id`.

Render the model files into the Rails application directory:

```sh
aontu render --out app gen/model.rb
aontu render --check app gen/model.rb
```

The first command writes the units named by this generator. The second
renders them again and compares their bytes with the files on disk.
It does not check files owned by other generators.

## Choose the generator for the output

| Generator | Reads | Writes under `app/` |
|---|---|---|
| `routes.rb` | Service root, entity paths, and actions | `config/routes.rb` |
| `migrate.rb` | Ordered entities, fields, and indexes | `db/migrate/*_create_*.rb` |
| `seeds.rb` | Ordered entities and prepared seed rows | `db/seeds.rb` |
| `model.rb` | Entity classes, associations, and required fields | `app/models/*.rb` |
| `api_base.rb` | Error definitions | `app/controllers/api/base_controller.rb` |
| `api_controller.rb` | Entity fields, paths, parents, and actions | `app/controllers/api/*_controller.rb` |
| `ui_controller.rb` | Entities and their parents | `app/controllers/*_controller.rb` |
| `views.aon` | Fields, labels, and route helpers | `app/views/*/*.html.erb` |

The [view generator](../gen/views.aon) uses ordinary aontu syntax with
ERB lines in backtick strings. The template marker mechanism does not
support ERB's delimited comment syntax, so this generator is an aontu
file rather than an ERB template.

## Understand the checks' limits

A `lossy:` message reports that a fragment contains target-language
text whose syntax aontu has not validated. The output can still render
successfully. Ruby syntax checks and Rails behaviour tests provide
separate evidence about that text.

`render --out` leaves files outside its unit list alone. When a rule is
removed or a generated path changes, review and remove the obsolete
file yourself. The [change-and-check guide](change-and-check.md)
shows the complete regeneration loop and a field change to try.
